7.1 PROBLEM STATEMENT / 02

เห็นผู้รับผิดชอบและสถานะร่วม
เมื่อมีหลายคนช่วยดูแลสัตว์เลี้ยง

โจทย์ออกแบบ

แชตและความจำไม่ได้เชื่อมงาน ผู้รับผิดชอบ และประวัติไว้ในรายการเดียว จึงออกแบบตารางสถานะร่วมสำหรับแต่ละบ้าน

เกณฑ์ที่ตรวจได้

สมาชิกเห็นงานเดียวกัน รับงานรายการเดียวกันสำเร็จเพียงคนเดียว และตรวจผู้ทำเสร็จพร้อมหมายเหตุได้

ประเมินความถูกต้องทางเทคนิคด้วยข้อมูลสังเคราะห์: docs/RESEARCH.md

7.2 SOLUTION / 03

งานหนึ่งรายการ
มีผู้รับผิดชอบได้คนเดียว

open→ claimed→ done
  • ผู้รับงานคืนงานได้ และเฉพาะผู้รับงานยืนยันว่าเสร็จได้
  • Transaction บันทึกสถานะกับauditพร้อมกัน
  • สองคำขอรับงานต้องได้200หนึ่งคำขอ และ409อีกคำขอ

ระบบกันรายการเดียวกันซ้ำ ไม่ได้พิสูจน์ว่ามีการดูแลสัตว์จริง และไม่กันการสร้างสองงานที่ความหมายเหมือนกัน

7.3 TARGET USERS / 04

สมาชิกบ้านเห็นตารางเดียวกัน

7.6 SUSTAINABILITY / 07

ติดตั้งเองและดูแลต่อได้
โดยไม่มี paid API ใน runtime

  • Node.js + SQLite และ Docker Compose สำหรับระบบขนาดเล็กหนึ่ง instance
  • ข้อมูลอยู่ใน named volume และมี online backup พร้อมตรวจ integrity
  • ต้นทุนคือเครื่อง พื้นที่สำรอง และเวลาบำรุงรักษา
  • รวมงาน สมุดบันทึก ปฏิทิน และสิทธิ์หลายบ้านใน flow เดียว

ยังไม่มี push/email notification, MFA และ email verification ไม่ใช่ระบบแนะนำการรักษา
