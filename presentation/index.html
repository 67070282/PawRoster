7.1 PROBLEM STATEMENT / 02

บ้านที่มีหลายผู้ดูแล
ต้องรู้ว่าใครรับงานและใครทำแล้ว

สมมติฐานปัญหา

แชตและความจำไม่ได้แสดงสถานะงานร่วมอย่างชัดเจน จึงอาจถามซ้ำ ทำซ้ำ หรือไม่มีคนรับงาน

หลักฐานที่ยังต้องเก็บ

ยังไม่มีผลสัมภาษณ์หรือทดลองจริง เตรียมสัมภาษณ์5บ้านและบันทึกเหตุการณ์ย้อนหลัง7วัน โดยไม่อ้างตัวเลขที่ยังไม่เก็บ

แบบเก็บข้อมูลและconsent: docs/RESEARCH.md

7.2 SOLUTION / 03

งานหนึ่งรายการ
มีผู้รับผิดชอบได้คนเดียว

open→ claimed→ done
  • ผู้รับงานคืนงานได้ และเฉพาะผู้รับงานยืนยันว่าเสร็จได้
  • Transaction บันทึกสถานะกับauditพร้อมกัน
  • สองคำขอรับงานต้องได้200หนึ่งคำขอ และ409อีกคำขอ

ระบบกันรายการเดียวกันซ้ำ ไม่ได้พิสูจน์ว่ามีการดูแลสัตว์จริง และไม่กันการสร้างสองงานที่ความหมายเหมือนกัน

7.3 TARGET USERS / 04

สมาชิกบ้านเห็นตารางเดียวกัน
ข้อมูลบ้านอื่นถูกแยกสิทธิ์

ผู้ใช้Use case และสิทธิ์
ผู้เริ่มบ้านสร้างบ้าน ชวนสมาชิก เพิ่มสัตว์และงาน
สมาชิกบ้านดูงาน รับงาน และเปลี่ยนงานที่ตนรับ
ผู้ดูแลระบบรันบริการ ตรวจlog เก็บbackup ตามสิทธิ์โฮสต์

สมาชิกบ้านเดียวกันมีสิทธิ์เท่ากัน บัญชีหนึ่งอยู่หนึ่งบ้าน ยังไม่มีถอดสมาชิกหรือinviteหมดอายุ

7.4 SOCIAL IMPACT / 05

ผลต่อผู้ใช้ต้องวัด
แยกจากจำนวนงานที่กดเสร็จ

Output ที่ระบบเก็บได้

งานสร้าง งานรับ งานเสร็จ และเวลาในaudit

Outcome ที่ต้องทดลอง

อัตรางานเลยเวลาและเวลาถามว่าใครทำแล้ว เทียบbaseline7วันกับtrial7วันในบ้านเดิม

เป้าหมายทดลองลดอัตรางานเลยเวลา20% ยังไม่ใช่ผลที่เกิดแล้ว

ขอconsent ใช้รหัสแทนชื่อ ไม่เก็บข้อมูลรักษา ระบุข้อมูลหายและปัจจัยกวน

7.5 TEAM AND NETWORK / 06

สมาชิกต้องอธิบาย
งานและการตัดสินใจที่ตนรับผิดชอบ

  • รายชื่อครบ4คนแล้ว หน้าที่จริงรอทีมระบุ
  • ใช้issue → branch → PR → review → merge เพื่อเก็บงานจริง
  • Git historyรอบเตรียมงานและAI-assisted baseline ไม่ใช่หลักฐานว่าทั้ง4คนทำงานแล้ว
  • ยังไม่มีpartnerหรือผู้เชี่ยวชาญที่ยืนยันร่วมโครงการ

งานค้างด้านทีมติดตามใน GitHub issue #3

7.6 SUSTAINABILITY / 07

เริ่มจากระบบขนาดเล็ก
ที่ทีมติดตั้งและดูแลต่อได้

  • Self-host ไม่มีpaid APIและไม่ใช้LLMในruntime
  • ต้นทุนคือhosting, backupและเวลาบำรุงรักษา ยังไม่ยืนยันผู้จ่าย
  • ข้อได้เปรียบจากความรู้ผู้ใช้ต้องสร้างและพิสูจน์ต่อ ไม่อ้างว่ามีแล้ว
  • ลำดับต่อไป: เก็บผลจริง → จัดการinvite/สมาชิก → recurring tasks → notification

Trade-off: หนึ่งinstance, SQLite local volume และmanual refresh
