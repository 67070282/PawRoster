# PawRoster — รายงานโครงงาน

รุ่นส่ง: 2.3.0 · วันที่จัดทำรายงาน: 13 พฤศจิกายน 2569

## 1. ปัญหาและแนวคิด

PawRoster ออกแบบสำหรับบ้านที่มีผู้ดูแลสัตว์เลี้ยงมากกว่าหนึ่งคน โดยรวมตารางงาน ผู้รับผิดชอบ และประวัติการดูแลไว้ในระบบเดียว สถานการณ์ที่ใช้กำหนดปัญหาคือการไม่ทราบว่าใครรับงานหรือทำแล้วเมื่อประสานงานผ่านแชตและความจำ ระบบจึงแสดงสถานะร่วมที่ตรวจสอบได้และป้องกันการรับงานรายการเดียวกันซ้ำ

ขอบเขตการประเมินของโครงงานคือความถูกต้องของระบบและการส่งมอบซ้ำได้ โดยใช้ข้อมูลสังเคราะห์และกรณีทดสอบที่ทำซ้ำได้ ไม่สรุปผลด้านสุขภาพสัตว์หรือการลดภาระงานของครัวเรือนเป็นตัวเลข

## 2. Solution และฟีเจอร์

- บัญชีเดียวเข้าร่วมได้หลายบ้าน แยกข้อมูลและสิทธิ์ตามบ้านที่เลือก
- งานดูแลมีสถานะ `open → claimed → done` ผู้รับงานคืนงานได้ และเฉพาะผู้รับงานยืนยันว่าเสร็จได้
- เจ้าของบ้านมอบหมายงาน กำหนดความสำคัญ งานซ้ำรายวัน/รายสัปดาห์ ค้นหาและกรองงานได้
- ข้อมูลสัตว์เลี้ยงมีประเภท สายพันธุ์ เพศ วันเกิดและหมายเหตุ พร้อมเก็บประวัติ ถังขยะ กู้คืนและลบถาวร
- สมุดบันทึกน้ำหนัก วัคซีน การพบสัตวแพทย์และบันทึกทั่วไป พร้อมนัดหมายและส่งออก CSV
- ปฏิทินรวมงานและนัดหมาย แยกวันนี้ วันที่มีนัด และวันที่เลือก พร้อมรายละเอียดรายวัน
- เจ้าของบ้านนำสมาชิกออกและบล็อก ปลดบล็อก เปลี่ยนรหัสเชิญ พักรับสมาชิก โอนสิทธิ์ และตรวจประวัติการจัดการบ้านได้

หนึ่งงานหมายถึงหนึ่งครั้งของการดูแล Transaction ป้องกันการรับหรือปิดรายการเดียวกันซ้ำ แต่ไม่ตรวจว่างานสองรายการมีความหมายซ้ำกัน และไม่ตรวจการดูแลทางกายภาพจริง

## 4. สถาปัตยกรรมและ DevTools

เว็บ HTML/CSS/JavaScript เรียก Node.js HTTP API ซึ่งตรวจ session สิทธิ์บ้านและกติกาธุรกิจก่อนอ่าน/เขียน SQLite ใช้ parameterized SQL, scrypt, HttpOnly cookie และ Transaction สำหรับการเปลี่ยนสถานะสำคัญ

Docker Compose รันแอปพร้อม named volume สำหรับฐานข้อมูล ในสภาพแวดล้อมอาจารย์ใช้ SSH เข้าสู่ `tuchsanai/devtools:2569_1` แล้วให้ Docker daemon ภายใน build และรันคอนเทนเนอร์แอปอีกชั้น รายละเอียดใน [RUN-IN-COURSE.md](RUN-IN-COURSE.md)

Git/GitHub เก็บประวัติเวอร์ชันและ PR ส่วน Jenkins ตรวจ source, secret scan, syntax, tests, build, publish image, deploy เฉพาะ main และตรวจ health/smoke หลัง deploy ดู [ARCHITECTURE.md](ARCHITECTURE.md) และ [OPERATIONS.md](OPERATIONS.md)

## 5. ผลการประเมินและประโยชน์ที่ยืนยันได้

Acceptance tests 32 กรณีผ่านทั้ง Windows และ Linux ใน image อาจารย์ ครอบคลุมสิทธิ์ การรับงานพร้อมกัน การคงอยู่ของข้อมูล สมุดบันทึก ถังขยะ และการจัดการสมาชิก Browser QA ตรวจ flow จริงและหน้าจอหลายขนาดผ่าน ผล Build/Health, online backup, integrity และ force-recreate ผ่าน รายละเอียดและแหล่งหลักฐานอยู่ใน [RESEARCH.md](RESEARCH.md)

ประโยชน์เชิงระบบที่ยืนยันได้คือสมาชิกในบ้านอ่านสถานะร่วมกันได้ รายการหนึ่งมีผู้รับงานได้คนเดียวตามกติกา และเก็บประวัติ/ข้อมูลต่อหลังเปิดบริการใหม่ได้ ประโยชน์เชิงสังคมที่คาดหวังคือช่วยการประสานงานดูแลสัตว์เลี้ยง แต่ไม่ได้วัดเป็นผลลดงานตกหล่นหรือผลทางการแพทย์

## 7. ความยั่งยืนและข้อจำกัด

ระบบติดตั้งเองได้ ใช้ SQLite และไม่มีค่าเรียก paid API หรือ LLM ใน runtime ต้นทุนการดูแลประกอบด้วยเครื่องที่ใช้รัน พื้นที่สำรอง และเวลาบำรุงรักษา จุดเด่นของโครงงานคือการเชื่อมตารางงาน สมุดบันทึก ปฏิทิน และสิทธิ์หลายบ้านใน flow เดียวที่มีหลักฐานทดสอบ ไม่อ้างความได้เปรียบทางการตลาดที่ยังไม่ได้วัด

เหมาะกับหนึ่ง instance และฐานข้อมูลบน local volume ยังไม่มี push/email notification, MFA, email verification และระบบยืนยันตัวบุคคล การบล็อกผูกกับบัญชี งานซ้ำสร้างครั้งถัดไปหลังงานปัจจุบันเสร็จ อ่านข้อจำกัดด้านความปลอดภัยใน [SECURITY.md](SECURITY.md)

## ลบบ้านถาวร (รุ่น 2.3)

เจ้าของบ้านเปิด **บ้านและสมาชิก → ลบบ้านถาวร** แล้วพิมพ์ชื่อบ้านให้ตรงและกดยืนยัน สมาชิกทั่วไปไม่มีสิทธิ์ลบบ้าน หากทุกคนต้องการย้ายออก ไม่จำเป็นต้องโอนเจ้าของให้คนที่ต้องอยู่ต่อ

การลบจะนำสมาชิกทุกคนออกและลบสัตว์เลี้ยงทุกสถานะ งาน สมุดบันทึก นัดหมาย ประวัติ และรายการบล็อกของบ้านนั้นถาวร รหัสเชิญเดิมใช้ไม่ได้ ข้อมูลไม่ย้ายไปบ้านใหม่อัตโนมัติ และกู้คืนผ่านหน้าเว็บไม่ได้ หากต้องเก็บข้อมูล ให้ผู้ดูแลสำรองฐานข้อมูลก่อนลบตาม [OPERATIONS.md](OPERATIONS.md)

บัญชี รหัสผ่าน และสมาชิกภาพในบ้านอื่นยังอยู่ ผู้ใช้ที่มีบ้านอื่นจะดูแลบ้านที่เหลือต่อได้ ผู้ที่ไม่มีบ้านเหลือยังเข้าสู่ระบบและเปิด **จัดการบ้าน** เพื่อสร้างบ้านหรือใช้รหัสเข้าร่วมบ้านอื่นได้ สมาชิกที่เปิดหน้าเดิมไว้กดอัปเดตข้อมูลเพื่อดูสถานะล่าสุด
