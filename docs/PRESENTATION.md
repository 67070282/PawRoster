## สถานการณ์สาธิต

ใช้บัญชีสังเคราะห์ A เจ้าของบ้าน, B สมาชิกบ้านเดียวกัน และ C อีกบ้าน เปิด browser contexts ที่ไม่ใช้ cookie ร่วมกัน

1. A เพิ่มสัตว์เลี้ยงและงาน B อัปเดตแล้วเห็นข้อมูลเดียวกัน A รับงานและกดทำแล้วพร้อมหมายเหตุ
2. A/B เปิดงานที่ยังไม่มีผู้รับ A รับก่อน B กดจากหน้าเก่า จะได้ conflict และมี claim สำเร็จเพียงหนึ่งรายการ
3. C ไม่เห็นข้อมูลบ้าน A แสดง R5 เพื่อยืนยันการเดา ID ถูกปฏิเสธ
4. เพิ่มบันทึกน้ำหนัก/นัดหมาย เปิดปฏิทินดูวันนี้ วันมีนัด และรายละเอียดวันที่เลือก
5. เปลี่ยนรหัสเชิญแล้วทดสอบรหัสเก่าถูกปฏิเสธ นำ B ออกและบล็อก จากนั้นสาธิตปลดบล็อก/พักรับสมาชิก
6. สาธิตถังขยะและกู้คืน ลบถาวรเฉพาะข้อมูลสังเคราะห์ที่เตรียมสำหรับสาธิต
7. เปิดหลักฐาน force-recreate/backup และ health revision ที่ตรงกับรุ่นทดสอบ

## ประเด็นอธิบายระบบ

- Transaction ทำให้การเปลี่ยนสถานะกับ audit สำเร็จหรือย้อนกลับด้วยกัน
- Server ตรวจ session, home membership และ role ทุกคำขอ ไม่อาศัยการซ่อนปุ่มอย่างเดียว
- SQLite อยู่ใน named volume จึงไม่หายเมื่อสร้าง container ใหม่
- งานซ้ำสร้างรายการถัดไปหลังปิดงานเดิม ไม่มี push/email scheduler
- Backend ยืนยันการบันทึกสถานะ ไม่ยืนยันการดูแลสัตว์ทางกายภาพ
